01요구사항 요약

기본 조건 4가지를 어떻게 만족시킬지 한눈에 정리했습니다.

⏱

3~5분 이내 플레이타임 설계로 보장

본 게임은 최대 180초 하드캡입니다. 일찍 죽으면 더 빨리 끝납니다. 결과·랭킹 확인까지 포함해 한 사이클이 3~4분입니다.

⇅

오프라인 + 웹 실행 가능

빌드 없는 HTML/JS 정적 파일이라 Netlify에 그대로 올릴 수 있습니다. 서비스 워커(PWA)로 첫 방문 후에는 인터넷 없이도 실행됩니다.

#

랭킹 + 로컬 기록 유지 조건부 가능

브라우저에서 SQLite를 쓰려면 sql.js(WASM)로 DB를 띄우고 IndexedDB에 저장하면 됩니다. 단, 기록은 해당 기기·브라우저 안에서만 공유됩니다(2장 참고).

Aa

닉네임 입력 가능

첫 실행 때 입력받고 마지막 닉네임을 기억합니다. 2~10자 한글·영문·숫자만 허용하며, 랭킹은 닉네임별 최고점으로 집계합니다.

02기술 검토

"Netlify 정적 배포 + SQLite" 조합이 실제로 되는지, 그리고 어디까지 되는지 확인했습니다.

항목판정내용
Netlify 정적 배포가능HTML/CSS/JS/WASM 파일만 있으면 드래그 앤 드롭이나 Git 연동으로 배포됩니다. 서버 코드가 없으므로 무료 플랜으로 충분합니다.
브라우저 안 SQLite가능sql.js(SQLite를 WebAssembly로 컴파일, 약 1MB)를 쓰면 브라우저 메모리에서 실제 SQL을 실행할 수 있습니다. DB 파일(Uint8Array)을 IndexedDB에 저장해 두면 브라우저를 닫아도 기록이 남습니다.
기록 공유 범위주의로컬 DB라서 같은 기기, 같은 브라우저에서 플레이한 기록끼리만 순위가 매겨집니다. 오락실 기계 한 대의 "HIGH SCORE" 화면과 같습니다. 전체 사용자 공용 랭킹이 필요하면 서버(Netlify Functions + DB)를 추가해야 합니다. 이는 확장 단계로 분리했습니다.
오프라인 실행PWA로 가능서비스 워커가 전체 리소스를 캐시하면, 첫 접속 이후 비행기 모드에서도 실행됩니다. 홈 화면 설치도 지원합니다.
file:// 더블클릭 실행제약파일을 더블클릭해서 열면 ES 모듈, WASM 로딩, 서비스 워커가 브라우저 보안 정책에 막힙니다. 로컬에서는 npx serve public처럼 간단한 서버로 띄워야 합니다. 꼭 더블클릭 실행이 필요하면 빌드 단계에서 단일 HTML로 묶는 방법이 있습니다(옵션).
저장소 대안폴백WASM 로딩에 실패하거나 시크릿 모드처럼 IndexedDB를 쓸 수 없으면 localStorage JSON으로 자동 전환합니다. 저장소 접근은 storage.js 인터페이스 하나로 감싸서 구현을 바꿔 끼울 수 있게 합니다.
결론

요구하신 구성은 그대로 실현 가능합니다. Vanilla JS + Canvas 2D로 게임을, sql.js + IndexedDB로 로컬 랭킹을, Service Worker로 오프라인을 처리하고, Netlify에 정적으로 배포합니다. 빌드 도구 없이 시작할 수 있습니다.

기술 스택

렌더링

Canvas 2D

도형 위주 네온 그래픽이라 엔진 없이도 충분합니다. 60fps를 목표로 requestAnimationFrame 고정 스텝 루프를 씁니다.

언어

ES Modules (JS)

번들러 없이 <script type="module">로 씁니다. 필요해지면 Vite로 옮기기 쉽습니다.

데이터

sql.js + IndexedDB

SQLite 문법 그대로 랭킹을 조회하고, DB 바이너리를 IndexedDB에 저장합니다.

배포

Netlify + PWA

정적 호스팅 + manifest.webmanifest + sw.js로 구성합니다.

04게임 컨셉 — NEON 180 (가칭)

"180초, 빛을 모으고 어둠을 피하라." 화면을 드래그해 빛나는 구체를 움직이면서 네온 조각을 모으고, 붉은 위험물을 피합니다.

조작

  • PC: 마우스를 움직이면 구체가 부드럽게 따라옵니다 (lerp 보간)
  • 모바일: 손가락 드래그. 상대 이동이라 손가락이 구체를 가리지 않습니다
  • 보조: 방향키/WASD, Space 대시, Esc 일시정지

오브젝트

  • ◆ 네온 조각 +10점 × 콤보 배율
  • ★ 골드 스타 +100점, 5초간 자석 효과
  • ● 위험물 닿으면 HP −1, 콤보 초기화
  • ✚ 실드 피격 1회 막기 (드물게 등장)

종료 조건

  • TIME UP: 180초를 버팀 → 남은 HP 1칸당 +500 보너스
  • GAME OVER: HP 3칸 소진 → 그 시점 점수로 끝
  • 두 경우 모두 결과 화면에서 자동 저장합니다

페이즈 타임라인 (난이도 곡선)

PHASE 1 · 0~60초위험물이 천천히 직선으로 움직입니다. 조작을 익히는 구간입니다.
PHASE 2 · 60~120초유도탄과 회전 장애물이 나오고 생성 속도가 1.5배가 됩니다.
PHASE 3 · 120~180초탄막 패턴이 나오고 골드 스타 출현율이 올라갑니다. 고위험 고보상 구간입니다.

점수 공식

// 조각 획득 시

// 종료 시

08데이터 설계 (SQLite)

sql.js에서 그대로 실행하는 SQL입니다. 스키마 버전은 PRAGMA user_version으로 관리합니다.

스키마

CREATE TABLE IF NOT EXISTS players (
  nickname    TEXT PRIMARY KEY,
  created_at  TEXT DEFAULT (datetime('now')),
  last_played TEXT
);

CREATE TABLE IF NOT EXISTS scores (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  nickname    TEXT NOT NULL,
  score       INTEGER NOT NULL,
  end_reason  TEXT,      -- 'timeup' | 'dead' | 'quit'
  survived_ms INTEGER,
  shards      INTEGER,
  max_combo   INTEGER,
  version     TEXT,      -- 밸런스 패치 구분용
  played_at   TEXT DEFAULT (datetime('now'))
);

CREATE INDEX IF NOT EXISTS idx_scores_rank
  ON scores(score DESC, played_at ASC);
CREATE INDEX IF NOT EXISTS idx_scores_nick
  ON scores(nickname, score DESC);

PRAGMA user_version = 1;

주요 쿼리

-- TOP 10 (닉네임별 최고점)
SELECT nickname, MAX(score) AS best,
       COUNT(*) AS plays
FROM scores
GROUP BY nickname
ORDER BY best DESC, MIN(played_at) ASC
LIMIT 10;

-- 내 순위 (:best = 내 최고점)
SELECT COUNT(*) + 1 AS rank
FROM (SELECT MAX(score) b FROM scores
      GROUP BY nickname)
WHERE b > :best;

-- 내 최근 20판
SELECT score, end_reason, played_at
FROM scores WHERE nickname = :nick
ORDER BY played_at DESC LIMIT 20;

db.js — 저장소 래퍼 (요약)

// public/src/data/db.js  (vendor/sql-wasm.js를 <script>로 먼저 로드)
const KEY = 'neon180.sqlite';
let db, saveTimer;

export async function openDB() {
  const SQL = await initSqlJs({ locateFile: f => `vendor/${f}` });
  const bytes = await idbGet(KEY);            // Uint8Array | undefined
  db = bytes ? new SQL.Database(bytes) : new SQL.Database();
  migrate(db);                                  // user_version 기준 스키마 적용
  navigator.storage?.persist?.();               // 브라우저가 데이터를 지우지 않도록 요청
}

export function saveScore(r) {
  db.run(
    `INSERT INTO scores (nickname, score, end_reason, survived_ms, shards, max_combo, version)
     VALUES (?,?,?,?,?,?,?)`,
    [r.nickname, r.score, r.reason, r.ms, r.shards, r.maxCombo, APP_VERSION]
  );
  clearTimeout(saveTimer);
  saveTimer = setTimeout(() => idbSet(KEY, db.export()), 300);  // 디바운스 저장
}

export function topRanking(limit = 10) {
  const st = db.prepare(TOP_SQL); st.bind([limit]);
  const rows = []; while (st.step()) rows.push(st.getAsObject());
  st.free(); return rows;
}
저장 데이터 관리 메모

sql.js는 DB 전체를 메모리에 올리고 통째로 export합니다. 한 판에 약 100바이트이므로 1만 판을 해도 1MB 수준이라 문제없습니다. 그래도 scores가 5만 건을 넘으면 닉네임별 상위 100건만 남기고 정리하는 로직을 넣습니다.

netlify.toml

[build]
  publish = "public"
  command = ""            # 빌드 없음

[[headers]]
  for = "/vendor/*.wasm"
  [headers.values]
    Content-Type  = "application/wasm"
    Cache-Control = "public, max-age=31536000, immutable"

[[headers]]
  for = "/sw.js"
  [headers.values]
    Cache-Control = "no-cache"   # SW 업데이트 즉시 반영

sw.js (캐시 우선)

const CACHE = 'neon180-v1';
const ASSETS = ['./', 'index.html', 'styles/ui.css',
  'src/main.js', /* ...모든 모듈... */
  'vendor/sql-wasm.js', 'vendor/sql-wasm.wasm'];

self.addEventListener('install', e =>
  e.waitUntil(caches.open(CACHE).then(c => c.addAll(ASSETS))));

self.addEventListener('activate', e =>
  e.waitUntil(caches.keys().then(ks => Promise.all(
    ks.filter(k => k !== CACHE).map(k => caches.delete(k))))));

self.addEventListener('fetch', e =>
  e.respondWith(caches.match(e.request)
    .then(r => r || fetch(e.request))));

  • 한 판이 180초를 넘지 않는다 (일시정지 시간은 제외)
  • 브라우저를 완전히 껐다 켜도 랭킹이 유지된다
